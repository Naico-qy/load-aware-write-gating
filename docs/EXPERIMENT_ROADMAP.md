> 主线不变：**负载盲的写入策略是可测量、可修复的缺陷**——方法 = 读回统计条件化门控。

## 0. GDN-2 官方协议（对齐模板，从仓库提取）

**模型**：`swa_gdn2_1.3B`（1,300,314,384 参数），18 层 × 18 头，block_size 4096，SWA 混合（local_window 2048）。
**递推**：`S_t = (I − k_t(b_t⊙k_t)^T) Diag(exp(g_t)) S_{t−1} + k_t(w_t⊙v_t)^T`——
channel-wise 擦除 b（key 轴）/ 写入 w（value 轴）/ 衰减 g，全部 token 条件化（memory-blind，CARVE 的批评点）。
**训练**：100B FineWeb-Edu，LR 4e-4，micro-batch 4–8，**4 节点 × 8 GPU（Slurm）**，Triton 内核。
**评测**：Wiki/LMB ppl/acc、常识推理、**RULER：S-NIAH-2@4K、S-NIAH-3@2K、MK-NIAH-1@4K**、
真实召回（SWDE/SQuAD/FDA/TriviaQA/NQ/DROP）、纯循环 + SWA 混合双设置。
**关键数字（recurrent 设置）**：MK-NIAH-1：GDN-2 37.8 vs GDN 27.8（+10）；S-NIAH-3@2K：89.8 vs 54.2（+35.6）；
混合设置下 MK-NIAH-1：48.0 vs 44.8。**他们自己承认优势集中在干扰密集的多键检索**——
这正是我们「负载感知」主张的目标场景。
**消融**：擦除门 b_t 贡献大部分增益。
**彩蛋**：脚本 job-name 暴露 NVIDIA 内部也有 **0.4B / 15B（512×4k）** 的小配置阶梯。

## 1. 资源可行性（诚实测算）

| 阶段 | 规模 | 算力需求 | 本机 4060 8GB | 租用（AutoDL 4090 ≈¥2/h；A100 80G ≈¥6–10/h） | 结论 |
|---|---|---|---|---|---|
| **2a 机制收尾** | ≤50M 参数，≤1B tokens/run | ~5–8h/run（本机实测吞吐 ≈0.6 TFLOPS 有效） | ✅ 可行（数天） | ✅ 更快 | **本机完成** |
| **2b 论文主规模** | 125–180M / 1–2B tokens | ~12h/run（4090） | ❌（单 run 一周） | ✅ 10 runs ≈ ¥300–600（4090） | **租 4090** |
| 2b+（对齐 HOLA） | 340M / 15B tokens | 8.9e19 FLOPs ≈ 50 GPU·天（4090）；A100 ≈ 2.5 天/run | ❌ | ✅ ≈ ¥250–400/run（A100） | **租 A100**（HOLA 先例：340M/15B 单作者发表） |
| **3 GDN-2 完整协议** | 1.3B / 100B tokens | 7.8e23 FLOPs ≈ 17h × 32 H100 起步 | ❌ | ❌ 单卡不可能；云上 ¥25k–60k | **需实验室集群或合作**；降级选项：760M/30B ≈ ¥3–6k |

**本机瓶颈的两个硬约束**：① 吞吐——我们的纯 PyTorch 分块实现有效吞吐 ≈0.6 TFLOPS（峰值的 ~5%），
优化（bf16/torch.compile/融合）也只到 2–3 TFLOPS；② **Triton 在 Windows 原生不可用**——
GDN-2 官方内核（FLA/Triton）必须 Linux（租用 AutoDL 即 Linux）或本机 WSL2。
**结论**：本机做机制与协议开发，租用 GPU 做规模训练——这是标准做法，不是妥协。

## 2. 三阶段方案

### Phase 2a：机制收尾 + RULER 协议本地化（本机，1–2 天）
1. **RULER 式 NIAH 生成器**进测试床（模板化，对齐 RULER 规格）：
   S-NIAH-1/2/3、MK-NIAH-1/2；语境 = 自然文本流（FineWeb 段落）；needle = key-value 句；
   记录每个 needle 的深度与负载。上下文 1K–4K（我们规模下的有效范围）。
2. **负载 × 容量二维扫描**（核心主张的直接检验）：P ∈ {8,16,32,64,128} × dk ∈ {8,16,32}，
   预测：门控增益是负载/容量比的函数——同比值下增益不变，跨比值随比值移动。
3. **通道级 b/w 门**（忠实 GDN-2）：当前 per-head 标量门升级为 channel-wise；
   我们的读回统计条件化叠加其上（+4 标量/头不变）。
4. **三档门控对比**（无人做过）：GDN-2 式 token 盲 / CARVE 式块边界读 / 我们逐 token 读——
   **匹配计算量**（我们的双 pass 是 2× 块成本，CARVE 式 ≈1×）→「逐 token 内容感知的价格」曲线。
5. 预注册：若逐 token 读在同算力下不优于块边界读 → 诚实报告，方法卖点转向占用维度。

### Phase 2b：论文主规模（租 4090/A100，¥300–600，3–5 天）
1. **规模**：125–180M 参数 / 2B tokens（≈15 tokens/参数，与 E1/E3 的 1.5 对齐），再升 340M/15B（对齐 HOLA）。
2. **架构**：纯 delta 栈（GDN 式 8–12 层 × 8 头），block 2048。
3. **臂**：GDN（标量 β）/ GDN-2 式（解耦通道门）/ **GDN-2+读回统计（ours）** / GDN-2+CARVE 式块边界读（算力对照）。
4. **评测**：Wiki/LMB ppl；**RULER S-NIAH-1/2/3 + MK-NIAH-1/2 @ 4K/8K/16K**（训练 2K，评测至 16K = 8×）；
   纯循环为主，+SWA 混合为辅。
5. **预注册预测**：我们的增益**集中在 MK-NIAH**（多键 = 高负载 = 我们的场景），S-NIAH-1 不劣。
6. 预算：4090 上 125M/2B ≈ ¥30/run；10 runs ≈ ¥300；升 340M/15B ≈ ¥250–400/run（A100）。

### Phase 3：GDN-2 完整协议对齐（需实验室资源）
- 1.3B / 100B / 32 GPU Slurm / RULER 全套 / 真实召回六件套。
- **诚实评估**：本机与散户租用均不可行（¥25k–60k + 运维）。
- **路径**：① 实验室/导师集群；② 与 GDN-2 组合作（他们开源了配方）；③ 降级 760M/30B（¥3–6k）作为
  「规模趋势」证据；④ 论文定位在 2b+（340M/15B = HOLA 先例规模），1.3B 协议对齐列为 revision 计划。

## 4. 立即行动（本机 Phase 2a）

1. `niah.py`：RULER 式数据生成器（S-NIAH-1/2/3、MK-NIAH-1/2，FineWeb 语境，可控深度/数量）
2. `run_e5_2d.py`：负载 × 容量二维扫描（P × dk，~24 runs，本机 1 天）
3. `run_e6_gates3way.py`：三档门控对比（token 盲 / 块边界 / 逐 token），匹配算力（~12 runs）
4. 通道级 b/w 门实现 + verify 扩展
